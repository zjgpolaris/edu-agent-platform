## 1. 迭代决策

下一轮让 AutoTutor 在自动选课时先检查内容是否可用，并让学生能直接选择可辅导的目标。目标是减少“已知道内容不支持，却先开课再阻断”的无效路径。

v1.50 已解决本地真实 Graph 和恢复；v1.51 已解决教学断言与可复现验收。接下来优先改善实际教学入口，复用这些工程能力验证变化，不再新建一套验收或生产证明流程。

核心规则：**自动规划可跳过暂不可用候选；用户显式指定的目标不能被系统静默替换。**

例子：学生弱点依次为“甲午战争影响”“洋务运动目的”。没有显式 focus 时，选择可辅导的洋务运动，并说明更高优先级目标暂缺内容；明确请求甲午战争时保留该目标，说明暂不支持，并让学生自己选择替代目标。

## 3. 目标、用户与范围

### 必须完成

1. 自动选课跳过无审核内容、无可用练习或无独立退出票的候选，按既有优先级选可用目标。
2. 显式 focus 保留原语义；不把其他目标的成功响应冒充原目标成功。
3. 学生可查看当前可辅导目标；阻断后可点击一个新目标重新开课。
4. 页面和会话证据解释“为什么选这个目标”，且刷新后与原 revision 一致。
5. 新行为通过真实 Graph + Legacy 回归，保持幂等、所有权、内容门禁和领域事务边界。

### 非目标

- 不补造 hard 题，不批量增加审核教材，不建立内容后台/CMS。
- 不更换 Agent 框架，不接入新的在线模型，不引入向量检索来计算目录。
- 不改生产 Canary、云资源位置、付费套餐或生产延迟阈值。
- 不改变退出票独立性或 verified mastery 语义，不保证无限重教。
- 不实现跨课程前置关系图、自动补全未知知识点或模糊相似目标的静默替换。

## 4. 可用内容能力查询

建议新增 `backend/agents/autotutor_catalog.py`，复用当前审核内容模型、加载器和题目校验逻辑。名称可按项目约定调整，不能复制另一套审核规则。

### 4.1 内部查询合同

输入为规范化目标、可选年级/册次、候选起始难度。输出至少包含：

- 规范化 objective_id、显示名称、grade、lesson、content_version；
- 可用起始难度、是否可开课、有限 reason code；
- 内容目录版本标识，供计划与实际取材的一致性检查。

“可开课”必须由现有有效内容判断得出：有审核通过的教学内容、有匹配难度练习，并至少存在一组符合既有独立性/迁移约束的练习—退出票组合。不能仅凭数组非空、不同题号或 review_status 字符串宣称可用。

选题需要随机/seed 排序时，必须限制在具备合格独立检验组合的候选内，或验证所有可能起始题均可接合法退出票。不能预检一组成功组合，实际却选另一道无法独立检验的题。

目录查询不写会话、不读取其他学生画像、不请求模型/embedding/远程检索。最多遍历本地内容包和当前候选一次；支持按内容版本缓存，但文件变更、失效和读取失败必须失效，不能沿用陈旧“可用”结论。

“可开课”不承诺任意答错次数后仍有新题。重教选题继续使用真实 assessment_history；耗尽后保留内容阻断，不能重复原题冒充新题。目录不展示“全程一定完成”一类承诺。

### 4.2 只读 API

拟新增 `GET /api/autotutor/targets`，可接受规范化 grade 过滤。沿用现有登录鉴权；学生、教师、管理员可读取相同的非个性化目录。无需传入 student_id，不借此增加读取画像的权限。

响应仅包含安全目录字段，例如：

```json
{
  "schema_version": 1,
  "catalog_version": "<content fingerprint>",
  "items": [{
    "objective_id": "<existing objective id>",
    "label": "洋务运动目的",
    "grade": "八年级上册",
    "launchable": true,
    "available_difficulties": ["easy", "medium"]
  }]
}
```

不得返回题干、选项正确性、答案键、原始来源文本、reviewer 身份、文件路径或学生信息。目录数量按服务端上限截断；未知年级返回空结果及明确提示，不能当作“全部年级”。未提供年级时可列出全部支持内容，逐项显示册次。

这是只读预览，不能作为后续 start 的授权凭证或不可变快照。start 仍需服务端重新确认。

## 5. 规划规则与执行边界

### 5.1 自动规划

1. 保持现有候选来源和顺序：weakpoints → weak_topics → recent_topics，去重后有界检查，建议上限 20。
2. 用既有解析器规范化 entity/aspect；解析不确定或无审核匹配时记为 unavailable，不做模糊替换。
3. 学生画像具有明确且受支持的年级/册次时，自动选择优先限定同册。无同册内容则不跨册自动开课；展示带册次的目录让用户选择。
4. 按现有错题次数规则选择 easy/medium；若期望难度不可用，允许在同一目标内降到较低难度并记录原因，不自动升难度。底层 `prepare_content(target_difficulty=hard)` 的阻断合同保持不变。
5. 选择首个可开课目标；记录跳过候选数量和安全理由。不可用弱点仍保留，不删除、标 mastered 或改 wrong_count。
6. 没有学情候选时，保留现有“鸦片战争影响”兜底，但仅在符合当前年级范围且内容可用时使用。不得兜底到不存在内容或跨册目标。
7. 有候选但均不可用时，返回兼容现有 `needs_content` 的明确结果和目录入口，不无界搜索其他学科，也不向用户宣称已经完成课程。

### 5.2 显式目标

focus 来自 URL、作业、错题或手动选择时，保持“本次请求目标不可更换”。目标不可用继续使用现有 `needs_content/content_blocked` 合同。

年级信息用于解释显式目标所属册次，不在本轮顺带新增会使既有显式入口失效的严格年级门禁。规范化不能把同一历史实体的 purpose 改成 impact。多个 focus 的既有第一项语义保持不变。

学生点击替代目标后才构成新学习意图：新 focus、新幂等键、新会话。旧阻断会话保留可恢复，不重写原目标。

### 5.3 观察、事务与一致性

目录检查是纯本地计算。计划选择、最终内容获取和选题约束整合进现有一次 ObservationBundle 获取，Graph 与 Legacy comparator 共用该输入，不重复检索或查询目录造成不同结果。

计划诊断建议保存为可选 `planning_decision`，包含 schema_version、selection_source、selected_objective_id、requested/selected difficulty、reason_code、skipped_count、catalog_version。不要保存整份候选画像或所有错题详情。

目录在选择后、实际获取前发生变化时重新验证：可有一次有界重算；仍不稳定则明确 needs_content，不返回过时可用结论。会话恢复读取已提交选择，不能按当前目录重算并改变历史目标。后续答题若内容撤销，沿用实际内容门禁。

诊断随 revision 经现有唯一领域事务提交。Graph/Legacy 的教学选择必须一致；只有纯诊断字段才可考虑 comparator 兼容排除，不能排除实际目标、难度或题目差异。无新增数据库表或 migration 的预期；若开发发现必要性，先在实现说明中论证。

## 6. 学生体验与证据

- 无 focus 的开课区域提供“自动安排”和“选择学习目标”。目录只展示课程名称、册次和可用状态，执行器名称仍留在现有诊断区域。
- 显式 focus 不因目录尚未加载而无限等待；保持现有开课与超时/恢复合同。
- needs_content 页面保留随问入口，增加当前可辅导目标；不只让用户回到复习页继续猜。
- 推荐读取失败有独立重试和有限等待，不影响已经开始的课程或已有 pending 恢复。
- 点击新目标走现有意图保存、同键重试与所有权校验。存在结果未知的 pending 时先同步，不偷偷发第二次开课。
- URL 更新与组件 key、sessionStorage 中 focus 一致；旧目录请求、旧会话请求和用户切换后的响应不能覆盖新选择。
- 课程摘要用简短文案解释选择，例如“优先巩固有教材支持的薄弱点”；不把被跳过目标表述为已解决。学生 demo-trace 与教师 evidence 复用白名单规划摘要，不暴露其他学生信息。

## 8. 测试与退出标准

### 必测场景

| 组 | 关键场景与预期 |
|---|---|
| 自动候选 | 最高优先目标无内容、第二目标可用 → 选第二项；只取有界候选；重复标签不重复取材 |
| 显式语义 | 相同输入显式指定不可用目标 → 保留原目标并阻断，绝不返回第二目标的课 |
| 空与年级 | 无画像、空目录、未知年级、无同册内容；不跨册静默兜底 |
| 难度 | 首选难度可用、只能降档、全部不可用；不能自动升档或放宽现有门禁 |
| 独立检验 | 有练习但缺合法退出票、只改题号的同题、部分练习无法配对 → 不误报可用 |
| 内容变化 | 缓存后移除/撤销内容、预览后内容变化、读取失败、版本变化 → 重新验证或阻断 |
| Graph/Legacy | 实际目标/题目一致、共享 ObservationBundle、无额外远程调用、CAS/重放副作用不变 |
| 权限/投影 | 匿名拒绝、目录无学生数据/答案、规划摘要白名单、教师原有关系授权保留 |
| 页面恢复 | 替代目标新键、新会话；双击；断网；刷新；pending 未决；旧响应晚到；切换用户 |

至少一个真实 API/Graph 用例重现“甲午战争影响优先但不可用 → 自动选择洋务运动目的”；另一个真实显式 focus 用例证明仍阻断。记录弱点前后数据，确认跳过不等于掌握。

增加负控：删除可用性过滤、将显式 focus 替换成推荐目标、伪造独立退出票资格时，对应断言必须失败。不能只检查节点或状态字符串。

验收要求：

1. 新增专项注册现有 runner；v1.51 内容、Graph 教学、review 包以及相关 parity/授权/恢复/事务回归通过。
2. Legacy 和 Graph 浏览器原有断言保持，新增自动规划/显式阻断/手动替代路径；lint、unit、build 通过。
3. 真实领域持久化路径有变化时执行现有 PostgreSQL 原子性检查；SQLite 不能替代 PostgreSQL 结论。
4. v1.51 review 包增加本轮规划案例，保留原教学成功/失败案例；完整 PASS 不可来自缺项、跳过或仅后台检查。
5. 交付记录列明实现 commit/dirty、输入来源、实际执行器、通过/失败/跳过和远端 CI。只作离线验收，不宣称真实 LLM 或云端性能改善。

## 9. 后续事项与回退

真实模型决策对照、扩大审核题库、公开站点部署延迟仍有价值，但本轮分别缺少必要的模型预算/场景、内容审核流程或资源路线，不与当前开发绑定。

回退选择策略与新目录 UI 时保留原内容门禁、Legacy/Graph 执行器和存量会话。新增 planning_decision 可选，旧状态兼容；不删除阻断记录、改变 mastery 或重放学习副作用。

设计时仅新增 spec、进行函数级隔离复现和只读 CI 核查；随后已按本 spec 完成开发与本地验收，结果及范围见交付记录。本轮开发未提交、push、触发 CI、发布或修改生产配置。
